# Data guide

## What is in this folder
- `demo_reviews_DEMO_ONLY.csv` - **SYNTHETIC. Written by `ml/generate_demo_data.py` from text templates.**
  It exists only so the pipeline and app can be demonstrated. It is NOT real data. Scores measured on it
  say nothing about real-world accuracy, and the app shows a "DEMO MODEL" banner while this model is in use.
  License: none needed, it is generated by this project's own script.

## Using a real dataset (recommended for your final report)
1. Download a labelled genuine/fake review CSV (see suggestions below).
2. Save it as `ml\data\dataset.csv`.
3. Make sure it has a **review text** column and a **label** column. Other columns are optional.
   Column names are matched automatically (see `ALIASES` in `ml/data.py`), e.g. `text`, `text_`, `review`,
   `stars`, `user_id`, `asin`, `date`.
4. Label meaning: fake = `fake`, `cg` (computer-generated), `spam`, `deceptive`, `1`, `true`;
   genuine = `genuine`, `real`, `or` (original), `truthful`, `0`, `false`.
   If your dataset uses other words, add them to `FAKE` / `GENUINE` in `ml/data.py`.
5. Retrain: `python train.py` (no `--demo`), then `python make_golden.py`, then rebuild the app.

## Suggested public datasets (I could NOT check these - I had no internet access)
Search for these names, read the dataset page, and **verify the license, label definition and
citation requirements yourself** before using or citing them:
- "Fake Reviews Dataset" (CG vs OR labels) - commonly shared on Kaggle. Labels CG / OR are produced
  partly by generation, so it tests "machine-written vs human-written" rather than real-world deception.
- Deceptive Opinion Spam Corpus (Ott et al.) - small, hotel reviews, crowd-written deceptive reviews.
- Yelp filtered-review datasets from academic work (YelpChi / YelpNYC / YelpZip) - labels come from
  Yelp's own filter, include reviewer and product IDs and dates (good for behaviour features).
- Amazon review datasets have no fake/genuine labels; they are only useful for unlabelled testing.

## What the cleaning step does (and reports)
Rows with empty text or an unrecognised label are removed. Identical review texts with *different* labels
are removed (conflicts). Repeated identical texts are reduced to one copy so a copy cannot sit in both the
training and test sets. Note this removes the "same text posted many times" signal from model training;
that signal is handled by the separate rule-based duplicate detector in the app.
